# Waymark — Android tester guide

## Joining the test

The organiser sends you the Google Play opt-in link once the test track is
available. Open it with the Google account added to the tester list, join the
test, and install **Waymark** from Google Play. The release app is
`app.waymark`; a development client is not needed.

Create your own account using an email address you can open on that phone and
a password of at least eight characters. If confirmation is enabled, follow
the email link on the same phone. Choose a display name; a profile photo is
optional.

For the closed test, stay opted in continuously for at least **14 days**.
Use the app during that period and send feedback. Installing the app alone
does not establish the organiser's required opted-in tester count.

## Things to try

Use made-up trip details and non-sensitive test notes/photos.

| Task | What to check |
|---|---|
| Create a trip | Name, destination, dates and optional cover save correctly; reopening the trip shows them |
| Invite a companion | Share the code with another tester; they can preview and join the same trip |
| Plan | Add/edit stops on both trip days; planned, confirmed and done states behave as expected |
| Dates | A new stop cannot start outside the trip's dates; an overnight end may run into the following day |
| Packing | Add quantities, assign items to people, pack/unpack them and try moving a loose tag into a bag |
| Shared notes | A note appears for the other member after they refresh or reopen the trip |
| Private notes | Hold the seal to open your note; it does not appear in your companion's account |
| Photos | Try a cover/avatar and cancel the picker once; declining a photo does not prevent planning |
| Reminders | Set a stop a few minutes ahead, allow notifications and exact alarms if requested, background the app, and check the reminder opens the right stop |
| Offline | Load a trip, disconnect Wi-Fi/mobile data, edit a stop or packing item, close/reopen the app, reconnect, and check the changes reach the other account without duplicates |
| Themes/accessibility | Try light/dark mode, larger system text and reduced motion; report unreadable or unreachable controls |
| Password reset | Sign out, request a reset, open the email on that phone, choose a new password and sign back in |
| Legal links | Open privacy and account-deletion links from Profile; they should load publicly |

Offline cache does not store private-note text. Private-note changes and trips
with a picked cover photo do not survive a restart while waiting to upload.
Joining a trip, uploading photos and deleting an account require a connection.

### Deletion test

Use a separate disposable account for Profile → Delete account; deletion is
permanent. Confirm the old login no longer works and that the other member
still has a shared trip. Keep your regular test account for the remaining
test period.

## Sending feedback

Use Google Play's private testing feedback or email **me@lfortiz.com**.
For a bug, include:

- Phone model, Android version and app version.
- Screen/feature and whether you were online or offline.
- The steps you took, what you expected and what happened.
- Whether it happens again, and a screenshot or recording if useful.

Do not include passwords, confirmation/reset links or sensitive trip data.
For general feedback: what felt useful, what was confusing, and what you
would want to change before planning a real trip.

## Suggested rhythm

- **First session:** sign-up, create/join a trip and try each main tab.
- **A later session:** offline/restart, reminders and password reset.
- **During the 14 days:** return to the shared plan, try a Play update if one
  is released, and send both bugs and usability feedback.

There is no required daily tap count. The organiser records real usage and
feedback, and verifies continuous opt-in in Play Console.
